# 5 · Solutions mapping: what's already being tried, and Bob's gap

Part of the [ibm-bob-2-hackathon-requirements](../requirements.md) research. Builds on [synthesis-04-patterns](04-patterns.md). Compiled 2026-09-26.

For each recurring pattern: the **research-paper solution** (a prototype that specifically targets it, with its measured result), then the **shipped industry product** doing something similar at scale, then **what's still missing** that the Bob skill is built to fill.

---

## Pattern 1: Comprehension is the bottleneck, not writing code

**Research paper solutions:**
- **CIAO** (arXiv 2604.08293, 2026): an LLM workflow that turns a GitHub repo into system-level architecture docs (C4 / ISO 42010 template) in minutes. 22 developers rated the output valuable and broadly accurate. Weak on diagrams and deployment views.
- **AI-Guided Exploration of Large-Scale Codebases** (arXiv 2508.05799): combines deterministic reverse-engineering (UML diagrams) with LLM-guided, intent-aware navigation, so the model explains code grounded in a structural view rather than free-associating.
- **Helveg** (arXiv 2507.10244): an interactive node-link diagram generated by static analysis, tested with 5 professional programmers as a stand-in for missing docs.

**Shipped product:**
- **Backstage TechDocs** (Spotify, open-sourced 2020, CNCF project): "docs like code" alongside the repo, auto-rendered. Spotify's own framing: *"New developers waste 30–50% of their time just figuring out who owns what, where documentation lives, and how to ship code"* — almost the exact number from Xia et al.'s 58% comprehension-time finding.
- **GitHub Copilot / Microsoft 365 Copilot GitHub connector**: markets itself explicitly on "accelerates onboarding and ramp-up — new hires can summarize README files, environment setup, and contributor guidelines with a single prompt" (Microsoft Learn docs). A UK case study (Capita) reports it lets a new developer "gain knowledge of the existing codebase without such extensive help from their buddy."

**Gap Bob fills:** CIAO and Backstage both produce *static, general* architecture docs for the whole team. Neither tailors depth or content to *one incoming hire's role and experience level*, and neither is generated from a single command tied to a specific start date. Bob's subagent split (architecture / tour / culture / role) personalizes the same underlying idea CIAO validated.

## Pattern 2: The knowledge that matters most (the *why*) is undocumented and tacit

**Research paper solutions:**
- **AgenticAKM** (arXiv 2602.04445, 2026): splits architecture-knowledge recovery across specialized agents (extract → retrieve → generate → validate) specifically to produce Architecture Decision Records from a repo. A 29-repo user study found this beats a single-prompt approach.
- **"An Explanation of Software Architecture Explanations"** (arXiv 2503.08628): proposes the **Explanation Window** — deliberately scoping what's explained and citing decision rationale, based on interviews with 17 professionals who said rationale is what's most often missing.
- **Knowledge Activation** (arXiv 2603.14805, 2026): packages institutional knowledge (architecture decisions, deployment runbooks) as agent-consumable "Skills" instead of documents for humans to interpret. Yahoo deployment, 67 engineers: 2.6 h/week saved, NPS +35.

**Shipped product:**
- **Glean**: enterprise search across Confluence/Drive/Slack, explicitly sold on "onboarding acceleration." Their Super.com case study: **20% shorter onboarding**, 1,500+ hours/month saved, driven partly by an auto-generated **org chart** so new hires understand who owns what.
- **Swimm**: code-coupled documentation with **Auto-sync** — walkthroughs that update themselves when the underlying code changes, directly targeting the "docs go stale, so nobody trusts them" problem LaToza et al. found.

**Gap Bob fills:** Glean and Swimm both *retrieve or preserve* existing knowledge. Neither one flags when the rationale is genuinely *missing* and routes that gap to a named human (the buddy). This is the more disciplined move: the skill's "cite the source, or write 'Unknown — ask your buddy'" rule turns Bob into a **coverage auditor**, not just a better search box, and it's the direct fix AgenticAKM's validate-agent step and LACY's human-curation step both point toward.

## Pattern 3: Pure AI underperforms; curated/hybrid AI wins

**Research paper solutions:**
- **LACY** (arXiv 2603.25391, 2026): the strongest evidence in the set. Deployed at Beko (30K+ LOC legacy finance system). Expert-curated AI-drafted code tours scored **83%** on comprehension quizzes vs **57%** for AI-only tours. Experts found *curating* less burdensome than doing live walkthroughs from scratch.
- **"How Developers Experience Debugging Unfamiliar Codebases with Code Tours..."** (arXiv 2607.26987): found LLM self-evaluation of its own tour quality is unreliable (sycophancy, confabulation) — meaning the fix has to be a human or a deterministic check, not another LLM grading the first one.

**Shipped product:**
- No major shipped product markets a "human curates the AI draft before a new hire sees it" workflow as a first-class feature; most (Copilot, Glean, Swimm) ship the AI output directly to the end user, sometimes with an edit history for correction *after* the fact.

**Gap Bob fills:** this is the PoC's single most defensible design choice, because it's the one place research (LACY) says the market's default behavior (ship AI output directly) is measurably worse. Bob's pipeline: draft → **deterministic path-check** → **named human approval gate**, before the pack reaches the new hire.

## Pattern 4: Turnover/skill gaps compound as you localize

No research-paper prototype targets this directly (see the gap noted in [synthesis-01-research-papers](01-research-papers.md): no peer-reviewed onboarding study specific to Malaysia/SEA). This pattern is evidenced by industry data alone (Aon, Hays, The Diplomat, Tee et al. — see [synthesis-02-articles](02-articles.md) and [synthesis-03-mixed](03-mixed.md)). It's the argument for **why this problem is worth solving in Malaysia specifically**, not a design input for the pipeline itself.

## Pattern 5: Structure around what newcomers actually do (real questions, run-it-first, progress checks)

**Research paper solutions:**
- **Code Compass** (arXiv 2405.06271): integrates documentation directly in the IDE with context-aware suggestions while navigating, reducing time spent switching to separate docs.
- **COSPEX** (arXiv 2107.02395): generates dynamic, execution-based summaries line-by-line as novices step through code, rather than a static write-up.
- **GazePrinter** (arXiv 2603.19855): visualizes expert *gaze paths* through unfamiliar code to steer novices along the route an expert would take; a 40-novice study found it measurably changed which path people took and reduced cognitive load.

**Shipped product:**
- **Swimm's "Playlists"**: ordered walkthrough sequences through real files, closest shipped analogue to a "code tour."

**Gap Bob fills:** these are all *interactive, IDE-embedded* experiences that require the tool to be installed and used live during exploration. Bob's PoC produces a **portable artifact** (the onboarding pack) that exists before day 1 and doesn't require the new hire to already be inside a specific tool to benefit from stop 1.

---

## Pattern 6: Depth should adapt to the person, not be one-size-fits-all

**Research paper solutions:**
- **TARS** (arXiv 2607.15948, 2026): a Theory-of-Mind agent that profiles a developer's expertise/role/style and adapts explanation depth accordingly. Controlled experiment, n=18: **26% faster** task completion, lower cognitive load.
- **Modelling-for-onboarding study** (arXiv 2510.07010): below-median new hires gained +15 points from a structured intervention; above-median hires didn't, and even regressed slightly — direct evidence that a single fixed depth is wrong for a mixed cohort.

**Shipped product:** none of the reviewed shipped tools (Backstage, Glean, Swimm, Copilot) vary output depth by the reader's seniority; they show the same docs to everyone.

**Gap Bob fills:** this validates the `experience: junior/mid/senior` field already in the hire file — it's a shipped-product gap, not just a research nicety.

## Extra mix: more solutions and a practice, not just tools

**Sourcegraph Cody / Code Search** (shipped product): grounds its AI chat in a deterministic search index across the *entire* codebase (and cross-repo dependencies), not just open files or an embedding guess. Sourcegraph's own pitch for this: "context is one of the most needed capabilities, and not many AI coding assistants are up to the task" (Leidos case study). This is the same insight as the arch-doc study in [synthesis-01-research-papers](01-research-papers.md) — grounding in real code beats a nicer-sounding but ungrounded explanation — applied to search instead of docs.

**Atlassian Compass** (shipped, now end-of-life as of 2026, being replaced by third parties like Cortex): a Backstage competitor built around **scorecards** — automated, visible checks of a service's health/ownership/docs coverage. Relevant pattern, not the product's survival: scoring *documentation completeness* as a first-class, checkable metric is exactly what Bob's deterministic self-check does at the level of one onboarding pack instead of a whole service catalog.

**"Good first issue" labeling** (a *practice*, backed by empirical research, not a product): Alderliesten et al., CHASE 2021 ("An Initial Exploration of the 'Good First Issue' Label for Newcomer Developers") and "A First Look at Good First Issues on GitHub" both study how OSS maintainers hand-label beginner-friendly tasks to solve exactly Steinmacher's "finding a way to start" barrier. It's low-tech (a label, not an AI) but it's the most widely deployed real-world fix for Pattern 5, at web scale, across virtually every popular OSS project. **Bob's "quick win" starter task is an automated version of hand-curated "good first issue" labeling**, generated per-hire instead of once per repo.

**Where this leaves the landscape:** every *individual* piece of Bob's design already exists somewhere — grounded search (Sourcegraph), architecture docs from a repo (CIAO), scorecard-style checks (Compass), curated-not-raw AI output (LACY), beginner task curation ("good first issue"), adaptive depth (TARS). No single reviewed product or paper combines all of them into one command that produces a **personalized, role- and experience-tailored, human-approved pack for one named incoming hire** before their start date. That combination, not any one technique, is where Bob's originality argument should sit.
