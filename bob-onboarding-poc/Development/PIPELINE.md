# Bob pipeline v2: final decided flow

Status: DECIDED (v2, 2026-09-26). Requirements: `requirements/00-index.md`. Everything runs inside Bob IDE (Agent mode). Do not depend on headless `bob run`.

**Trigger:** `/onboard` (optionally `/onboard @instances/<client>/instance.yaml @instances/<client>/hires/<name>.yaml` to prefill). Skill: `.bob/skills/onboarding-pipeline/SKILL.md` (the authoritative step list; templates in `templates.md`).
**Before the first run:** set Bob's Permissions (see README "Permissions"). Then `python scripts/selftest.py` should print `ALL OK`.

## Stages
| # | Stage | Output (under `onboarding/<slug>/`) | Gate |
|---|-------|-------------------------------------|------|
| 0 | Intake (ask codebase, company, newcomer name/position/email, start/end dates, manager/buddy) | `intake.yaml`, timeline table | required fields present |
| 1 | Generate: 4 parallel subagents (company & role, architecture & tour, issue scan, tech stack) | `context/*.md`, `context/issues/ISSUE-NNN-*.md`, `context/scripts/install_deps.py` | stage 3 |
| 2 | Merge | `pack.md`, `manager.md`, `context/timeline.md`, `context/AGENTS.md`, `context/README.md`, and if `video: yes` `storyboard.json` (the video script) | stage 3 |
| 3 | Deterministic check: `pipeline_tools.py check` (citations, issue files, and the storyboard: schema, refs real in the repo and in the pack, narration rules and length) | prints `OK` | must pass |
| 4 | Flag | `flagged.md` (3-6 bullets) | none |
| 5 | **Human approval** (flagged list + issue INDEX, not the full pack) | | **STOP, wait for the user** |
| 6 | Render: `render_pdf.py` + `pipeline_tools.py bundle` | `<company>-onboarding-<slug>.pdf`, `…-context.zip` | stage 7 |
| 6b | Video (optional): `make_video.py` renders `storyboard.json` (slides in the PDF's style, Piper voice, captions, real code excerpts, ffmpeg) | `<company>-onboarding-<slug>-tour.mp4` | failure asks the user, never silent |
| 6c | Package: `pipeline_tools.py guide` (newcomer's start guide: `context/README.md` + `email-newcomer.md`, generated) then `bundle` (the zip) | `context/README.md`, `email-newcomer.md`, `…-context.zip` | none |
| 7 | `pipeline_tools.py deliverables`, then send via MCP `send_onboarding_email` | 2 emails (or dry-run log); the newcomer's carries the PDF, the zip and, when `video: yes`, the MP4 | approval done; deliverables OK or the user's explicit OK to send without a file |

Every stage is logged (`run-log.md`) with start/end timestamps: that is the pipeline's own timeline and the demo timing evidence.

## Decisions (do not reopen)
- Failures are handled by a bounded fix loop (skill `<FixLoop>`, `requirements/10-fix-loop.md`): `pipeline_tools.py fix` (free mechanical repairs), then Bob edits per a message-to-fix table, with `pipeline_tools.py guard` capping attempts at 3 per stage and stopping early when the same problems come back. On STOP the user is asked. Fixes never delete or invent facts silently, never change a check to make it pass, and after approval change only layout and wording.
- The newcomer's start guide (what to do with the PDF, video and context folder; Bob IDE setup) is generated by `pipeline_tools.py guide` at stage 6c, not written by Bob: same text in the email body and `context/README.md`, an accurate file list, the video/PDF named only if they exist, Bob IDE facts taken from Bob's docs. It is newcomer-only: never added to `manager.md` or the manager's email. Its one non-obvious step: `AGENTS.md` must be copied to the workspace root, because Bob only auto-loads a root `AGENTS.md`.
- Naming is deterministic code, not LLM output: `pipeline_tools.py slug` (folder/file slug: ASCII, Windows-safe, collision-safe with `--email`) and `pipeline_tools.py names` (the pdf/zip/mp4 file names, `<company>-onboarding-<slug>…`, so attachments are self-describing in an inbox). Issue files are `ISSUE-NNN-<slug>.md`, numbered without gaps; stage 3 enforces it. See `requirements/09-naming.md`.
- Human gate stays, narrowed to the Flagged list + issue INDEX. Tool auto-approve is not approval.
- No dashboard, no Q&A loop. Static PDF + context zip; fresh pack per hire.
- Newcomer needs no GitHub/Bob account to read the PDF; the context zip is loaded into their own Bob.
- Target codebase is chosen at intake, READ-ONLY. Never modify it; never copy secrets or client data into issues, pack, or repo.
- Issues: one `.md` each, capped by `max_issues` (default 10, Bobcoin budget).
- Dates come from `pipeline_tools.py timeline`, never from the LLM.
- Only the pip + npm manifests are auto-installed (`install_deps.py`); no sudo, no system packages.
- Video is a bonus output and optional (`video: yes|no` at intake). The script (`storyboard.json`) is LLM work written at stage 2, so stage 3 checks it and the stage 5 gate covers it; rendering is deterministic code after approval. It only re-tells the pack: every fact and `path:line` must already be in `pack.md`. The video's tools are offered right after intake (one question) and installed by Bob with `make_video.py --setup`: pip only, no admin rights, no PATH edits (`piper-tts`, the ~63 MB voice, and a bundled `imageio-ffmpeg` only if the machine has no ffmpeg). The video is part of the newcomer's delivery when `video: yes`, so a missing dependency or failed render is never dropped silently: `deliverables` fails and Bob asks whether to fix it or send without it. Code excerpts come from the read-only target repo and credential-looking lines are masked. The MP4 is not in the context zip (that is for the newcomer's Bob).
- Video length: narration budget 170 s (`WORDS_PER_SEC`/`VIDEO_MAX_S` in `pipeline_tools.py`); render check cap `MAX_S` = 180 s in `make_video.py`. Confirm the submission form's limit before relying on it.

## Email tool spec (Bob builds it, stage 7)
`send_onboarding_email(to, subject, body, attachment_paths[], reply_to)` (newcomer call: the `pdf`, `zip` and, when built and under 20 MB, `mp4` paths printed by `pipeline_tools.py names`): SMTP from env `SMTP_HOST/PORT/USER/PASS` (never hardcoded/committed); `--dry-run` logs to, subject, reply_to, attachment names; test inbox (Mailtrap/Ethereal) for the demo. Code at `mcp/onboarding-mail/server.py`; registered in `.bob/mcp.json` by `pipeline_tools.py check-mcp --fix` (the `/onboard` preflight; per-machine file, git-ignored; `--dry-run` when no SMTP creds). Pass `brand_name`/`brand_accent` from `intake.yaml` on both calls (absent = neutral header). Call 1: newcomer, PDF + context zip, `reply_to` = buddy (else manager). Call 2: manager, `manager.md` as body. Addresses come from `intake.yaml` only; never invent.

## Build order (cut from the bottom)
1. Intake + generation + check + flags (alone is a valid demo). 2. Approval gate. 3. PDF + bundle. 4. Email (dry-run only if short on time).
